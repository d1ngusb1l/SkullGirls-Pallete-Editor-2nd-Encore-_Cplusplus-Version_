Phase 1: independent transformation rules

2. Allow two or more unrelated rules to coexist and activate simultaneously without changing each other's links, triggers or enabled state. Aggregate them through a single owner of the native redirect table.
3. Define and document deterministic behavior for overlapping source bands/shades, priorities/ties, static color links, existing native records, and chained destinations. Verify the game's actual native record precedence instead of assuming list order works. Never silently let one rule erase another. If a combination is unsupported, reject it clearly before writing.
4. Preserve the base/native appearance when no rule is active. Each rule's manual preview must be independent; preview in the isolated sprite window must not mutate the live fighter or saved file. Avoid calling unsupported effects game-equivalent.

Phase 2: character resources and persistent character-dependent triggers

2. Distinguish resource amount, threshold availability, the activation event and any persistent active boost/mode. 3. Have the user create controlled observations: baseline, gain, threshold crossing, activation/spending, expiration/cancel, tag out/back, fresh match and mirrors on different teams.
